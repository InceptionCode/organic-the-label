# Contributing

## Commit messages — Conventional Commits

Every commit message (and every **PR title**, since we squash-merge) must follow
[Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<optional scope>): <description>
```

```
feat: add dark mode toggle
fix: resolve auth token refresh bug
fix(cart): stop stale cart id from breaking checkout
docs: update README setup steps
chore: update dependencies
refactor(store): extract filter normalization into lib
test(compositions): cover the filter URL-sync regression
feat!: drop support for the legacy /explore route
```

A breaking change is either a `!` after the type/scope, or a `BREAKING CHANGE:` line in the
commit body.

### Types → CHANGELOG sections

| Type | Section | Bump |
| --- | --- | --- |
| `feat` | 🚀 Features | minor |
| `fix` | 🐛 Bug Fixes | patch |
| `perf` | ⚡ Performance | patch |
| `refactor` | 🚜 Refactor | patch |
| `docs` | 📚 Documentation | patch |
| `test` | 🧪 Testing | patch |
| `ci` / `build` | ⚙️ CI & Build | patch |
| `style` | 🎨 Styling | patch |
| `chore` | 🧹 Chores | patch |
| `revert` | ◀️ Revert | patch |
| `feat!` / `BREAKING CHANGE:` | 💥 Breaking Changes | major |

`chore(deps…)`, `chore(release…)` and `chore(changelog…)` are excluded from the changelog.

### Enforcement

- **Local:** a husky `commit-msg` hook runs `commitlint` on every commit. Bypass with
  `git commit --no-verify` when you really need to.
- **CI:** `.github/workflows/commitlint.yml` lints the PR title on every pull request to
  `main` / `dev`.

## Changelog & versioning

`CHANGELOG.md` is **generated by [git-cliff](https://git-cliff.org)** from commit history — never
edit it by hand.

- On every push to `main`, `.github/workflows/changelog.yml` regenerates `CHANGELOG.md` and
  commits it back (`chore(changelog): update [skip ci]`).
- To cut a release locally:

  ```bash
  pnpm release
  ```

  This computes the next version from the commits since the last tag, runs
  `git-cliff --bump`, updates `package.json`, commits `chore(release): vX.Y.Z`, and tags
  `vX.Y.Z`. Then:

  ```bash
  git push --follow-tags
  ```

  Pushing the tag triggers `.github/workflows/release.yml`, which publishes a GitHub Release
  with that version's changelog section as the notes.

- Preview the changelog any time without writing the file:

  ```bash
  pnpm exec git-cliff --unreleased
  ```

### One-time setup

A baseline tag must exist before the first `pnpm release`:

```bash
git tag v1.6.0
git push --tags
```

### Branch-protection note

`changelog.yml` pushes directly to `main`. If `main` has branch protection with "require a pull
request", add `github-actions[bot]` to the bypass list (Settings → Branches), or swap the push
step for one that uses a Personal Access Token.
